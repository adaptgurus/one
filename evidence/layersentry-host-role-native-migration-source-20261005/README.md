# Native migration host-role source candidate

The native OpenNebula KVM owner retains migration execution; LayerSentry supplies
protected role admission and finite socket observation. The owner binds the target
migration listener/data URI to the approved host address and rejects transport
overrides. The root helper independently verifies hardware, profile generation,
interface/address/route/MTU and exact QEMU VM identity. Tests use synthetic responses
and do not establish a real native migration path.

A successful native migration with absent/foreign/stale socket evidence remains
explicitly unqualified. Its native return code is preserved so OpenNebula does not
destroy the migrated target or replay the operation merely because evidence is
missing. Durable operation/history-epoch receipts and LayerSentry verification
consumption remain required before completion can be asserted. Local-disk streaming
is closed pending its own approved data-path proof. No modified native driver has
been installed and no management or storage networking has changed.

The pre-existing VM Security State deploy hook was reviewed and shell checked; it
invokes the finite preboot helper before native VM creation for a marked recovery
and fails closed if the helper/version/restore is unavailable. This is source
validation, not TPM/Secure Boot recovery proof.
